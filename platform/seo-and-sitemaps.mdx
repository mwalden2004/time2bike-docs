Time2Bike provides page information and a sitemap to help search engines and
social platforms discover public pages. Those services decide whether, when,
and how to show a page or preview.

## What happens automatically

- Eligible public event, organization, team, and series pages are included in
  the site's sitemap.
- Each page gets a title and summary built from what you've already filled in.
- Pages provide preview information, including the event name, description,
  and available banner. Social platforms may cache it or display it differently.
- Draft events require organizer access. Keep private information out of any
  page you intend to publish.
- **Unlisted** events can be opened by anyone with the link. They are omitted
  from public listings and marked for search engines not to index. This is
  not access control; recipients can share the link or copy the content. Use
  **Published** when you want the event listed publicly.
  → [Event settings](/organizers/events/event-settings)

Search engines may retain previously indexed pages until they revisit them.
See [Google's explanation of noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing).

## Preparing your public page

<AccordionGroup>
  <Accordion title="Write a real description" icon="align-left">
    Put your event name, discipline, city, and state in the first sentence of
    your event description. That's what people search for ("gravel race
    Bentonville") and it's what search engines read first.
  </Accordion>
  <Accordion title="Upload a good banner" icon="image">
    Use a clear banner that remains readable at preview size. Preview the link
    on the social platforms where you plan to share it.
  </Accordion>
  <Accordion title="Use one link everywhere" icon="link">
    Put the same `time2.bike/events/your-event` link in every post, email, and
    flyer so riders can find the same event details.

    And don't change your web address once you've publicised it. Old links
    don't redirect. → [Web addresses](/platform/slugs)
  </Accordion>
  <Accordion title="Keep the same link next year" icon="repeat">
    A recurring event provides a reusable address for its current occurrence,
    while each occurrence keeps a dated page. Keep the recurring event and its
    address in place if you plan to reuse that link. → [Recurring events](/organizers/events/recurring-events)
  </Accordion>
  <Accordion title="Get shared early" icon="share-nodes">
    Ask your venue, clubs, and sponsors to link to the event page so riders can
    find current details.
  </Accordion>
</AccordionGroup>

## Knowing what worked

Time2Bike records supported campaign tags and referrer information when they
are available. View these under **Event → Analytics → Attribution**.

Attribution can be incomplete when a rider changes browsers or tabs, blocks
storage, or follows an untagged link. Treat it as an indication of where
registrations came from, not a complete record of every visit.

→ [Event analytics](/organizers/events/event-analytics)

## Rider profiles

The profile-management pages require sign-in and are marked not to be indexed.
A rider's name can still appear on public event results and start lists, which
may be indexed separately. **Account → Privacy** provides export and deletion
tools; it does not provide a switch that hides all published race records.

→ [Privacy](/riders/account/privacy)
