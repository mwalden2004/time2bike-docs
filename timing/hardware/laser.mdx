Time2Bike can use beam-break gate boxes to trigger starts and finishes. A mapped
box reports a beam break to a USB-connected base station, and the timing screen
uses it for the selected action when the panel is armed.

Test the complete setup on the course before relying on it. Detection, alignment,
clock state, radio coverage, and the bridge laptop all affect the timing record.

This example uses simulated box readings and a demo timing laptop.

## The equipment

| Piece | Role |
|---|---|
| **Gate boxes** | Detect and timestamp beam breaks on the course |
| **Base station** | Receives box messages by radio and connects to a laptop by USB |

Compatible boxes support relaying messages through neighbouring boxes. Terrain,
distance, interference, and box placement affect coverage; test each gate at its
race-day position.

## Getting connected

<Steps>
  <Step title="Plug the base station into a laptop">
    Use a browser with Web Serial support, such as Chrome or Edge on a supported
    desktop system. The browser must grant access to the selected device.
  </Step>
  <Step title="Open the laser panel on the timing screen">
    Click connect and pick the base station from the browser’s device list.
  </Step>
  <Step title="Add your boxes">
    Add each box ID and confirm you can see its current status.
  </Step>
  <Step title="Map each box to its job">
    Select the start, finish, or lane action that box should trigger. Confirm
    the staged rider or lane before testing a crossing.
  </Step>
  <Step title="Check clock state, then arm">
    Check box clock status, alignment, battery, and communication. Arm the panel
    and perform a test pass; verify that it reaches the intended timing record.
  </Step>
</Steps>

## Timestamps and clock state

When a usable box timestamp is available, the timing action uses that timestamp
instead of the message’s arrival time. GPS lock, clock holdover, and fallback
clock states are shown in the panel; they should not be treated as equivalent
levels of accuracy.

If the box timestamp is absent or outside the accepted clock range, the panel
can fall back to timing on arrival and shows a warning. Network or radio delay
then affects the timestamp. Investigate those passes before accepting close
results, using your backup timing evidence.

The **delivered** figure compares host arrival with the box timestamp. It can
include disagreement between their clocks; it is not a certified timing-error
measurement.

## The bridge laptop and remote operators

The laptop connected to the base station acts as the bridge. While connected,
other timing operators can view shared box status and request supported controls.
A remote command needs to reach the bridge and box before it can take effect.

Keep the bridge laptop powered, connected, and its timing page running. Loss of
remote visibility does not by itself stop the bridge from recording, but it also
does not prove that passes are reaching the timing log. Check the bridge and its
sync queue after an interruption.

## Speed readings

Speed is estimated from a detected wheel gap and the configured wheelbase
(default **1.2 m**). Actual wheelbase and the quality of the detected breaks affect
the estimate. Missing or unclear wheel detections can leave a pass without a
speed reading; check the timing record separately.

## Watch the alerts

| State | What to check |
|---|---|
| **Align** | Alignment mode suppresses timing triggers; return the box to timing before a run |
| **Quiet** | The box is not transmitting passes; restore communication and check its record |
| **Storm** | Radio activity has paused after a suspected sensor fault; investigate the sensor |
| **Deaf** | Test mode simulates a dead link; leave test mode before racing |

Review the panel’s countdowns and available controls rather than waiting for a
mode to expire. A missing heartbeat means communication is stale, not proof that
the box has stopped sensing or that its records are recoverable.

## If a pass goes missing

Check the box, bridge log, sync queue, and any sequence-gap warning. Compatible
boxes can retain passes on a memory card when card logging is working. Recovery
depends on the record having been written and remaining readable; keep a backup
timing method and contact support for help with available box logs.
