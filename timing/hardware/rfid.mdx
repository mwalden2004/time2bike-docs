If you already own an RFID timing pad, you can feed its reads straight into the
timer instead of typing bibs by hand.

<Note>
  The importer matches the bib reported by the reader against the selected
  start lists. Configure chip-to-bib mapping in the reader’s software, then
  verify the mappings, race selection, and test crossings in Time2Bike before
  racing. An incorrect mapping can credit the wrong rider.
</Note>

## Watching your reader's file

Best when your reader's software writes to a file on the machine you're timing
from. The importer currently supports **RFIDServer exports** in the format
shown below.

<Steps>
  <Step title="Open the RFID panel on the timing screen">
    Open **RFID timing pad**, then expand **RFID CSV import**.
  </Step>
  <Step title="Click 'Pick CSV & watch' and choose the file your reader writes to">
    <Frame caption="Demo data. Names, races, and results are fictional.">
      <img src="/images/timing/rfid-csv.png" alt="Expanded RFID CSV import panel with demo races and Pick CSV & watch control" />
    </Frame>
  </Step>
  <Step title="Leave the tab open">
    The watcher checks for new lines while it is running. Monitor its status
    and compare imported crossings against the reader’s log; file access,
    browser suspension, filtering, or invalid rows can interrupt imports.
  </Step>
</Steps>

Each line needs a bib and a timestamp. A typical line looks like:

```
2,205,205,"2025-09-27 10:37:01.926"
```

Extra columns are ignored.

<Note>
  **Continuous watching needs Chrome or Edge.** In Safari and Firefox you get a
  one-shot import instead, so re-pick the file to pull in newer rows. On a race
  day where the pad is running all afternoon, use Chrome.
</Note>

## Importing a file from a race that already happened

Reads that predate the recorded start are held for review. The panel can
suggest moving the start to the first crossing in the file so those reads can
be applied.

Check that proposed time against the actual gun before accepting it. A first
read can be a warm-up, a start-line read, or a finish well after the gun; it does
not establish when the race began. Also check the reader’s clock and time zone.
Use **Set the start time** or **Correct the start time** with your verified
backup record when the suggested time is wrong, then review the imported results.

## Things worth knowing

<AccordionGroup>
  <Accordion title="It resumes where it left off" icon="bookmark">
    The watcher stores its file position in this browser. That position can
    be lost if browser data is cleared.

    **Reset cursor** re-reads the file from the top. Duplicate detection
    recognizes matching read identifiers, but changed timestamps, bib mappings,
    or file contents can produce different records. Check the resulting counts
    and any duplicate flags.
  </Accordion>
  <Accordion title="Check the listening races first" icon="tag">
    Choose the races in **Listening races** before starting the watcher.
    Reads are matched to bibs on those start lists.
  </Accordion>
  <Accordion title="Unknown bibs need attention" icon="circle-question">
    Reads for bibs outside the start lists are held. The panel lists those
    bibs and offers **Add riders as unidentified** so you can keep their
    crossings and identify them later. Tags with no bib need to be mapped
    in the reader software.
  </Accordion>
  <Accordion title="Mats can map to split points" icon="map-pin">
    If your reader reports which mat produced a read, you can tie each mat to a
    named split point: **Timer setup → Races**, pick the race, then set the mat
    id on that timing point. Reads from that mat land on that split
    automatically.

    → [Recording points](/timing/screen/recording-points)
  </Accordion>
  <Accordion title="The watcher stops if the tab goes to the background" icon="triangle-exclamation">
    Some machines pause background tabs. Keep the timing tab in front, and if
    reads stop arriving, re-pick the file. If you swapped drives, the browser
    lost track of the file, so re-pick it.
  </Accordion>
  <Accordion title="You can still type" icon="keyboard">
    The number box keeps working while the watcher runs. If a chip doesn't read,
    type the bib and it's recorded the same way.
  </Accordion>
</AccordionGroup>

## Dual slalom

In two-lane racing the pad reads turn themselves into lane finishes: while a run
is in flight, a read for a plate that started in the red lane records a red-lane
finish. Reads for plates not currently on course are dropped.

A **Listening for plates** panel shows exactly which two bibs the watcher is
waiting for.

<Warning>
  A pad mounted near the start line will fire on warm-up runs. Either move the
  pad or plan to clean up the extra reads afterwards. Use the **Listening for
  plates** panel to check the expected riders, and verify that each detected
  crossing belongs to the intended race run.
</Warning>

## Reading from another machine

If the pad is on a different computer from the one you're timing on, Time2Bike
supports timing integrations over the network. Contact support to check
compatibility and setup for your reader before race day; do not assume an
arbitrary reader or file format will work without testing.

## You don't need any of this

An RFID pad is an option, not a requirement. Manual bib recording is also available. Choose and test a timing method
that meets your event’s rules and required accuracy.
