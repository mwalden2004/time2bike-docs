If you're moving from **BikeReg**, **RunSignup**, or another platform, you can import your historical data without retyping it. Imports live under **Organization → Imports** and follow the same upload → map → preview → commit flow regardless of type.

{/* IMAGE NEEDED: Organization → **Imports**, on the preview step before committing */}

## What you can import

| Type | Scope | What it does |
|---|---|---|
| **Contacts** | Organization | Adds people to your contacts list so they can be invited to events, including their emergency contact. |
| **Registrations** | Event | Adds participants to a specific race, with optional bib and category. |
| **Results** | Event | Loads finish times and placements onto a race. |

Contacts are org-wide. Registrations and results are imported from inside an event under **Event → Imports**.

## The four-step wizard

<Steps>
  <Step title="Upload">
    Drop in a **CSV** or **PDF**. Max 10 MB. We never crawl third-party
    platforms, so you have to upload the file yourself.
  </Step>
  <Step title="Map columns">
    Time2Bike makes its best guess at which column is the first name, last name, email, plate, etc. Adjust the mapping if anything's wrong. A sample of the first few rows is shown so you can verify.
  </Step>
  <Step title="Preview">
    We run a **dry run** and show you exactly how many rows would be **created**, **updated**, **skipped**, or have **errors**. Click **Download errors** to grab a CSV of the rows that need attention.
  </Step>
  <Step title="Commit">
    Confirm. Rows are written one at a time; if any single row fails, the rest still go through. You get a final summary.
  </Step>
</Steps>

Nothing is written to your data until you click **Commit** on step 4.

## Leaving and coming back

An import is saved as you go, so you don't have to finish it in one sitting.
Your column mapping, your answers about which race each row belongs to, and
your "same rider?" decisions are all stored on the job — close the tab, go look
something up, come back tomorrow on a different machine, and it's all still
there. The wizard shows **Progress saved** once it has caught up.

To pick one back up:

- The **Imports** page lists unfinished jobs with a **Resume** link.
- Starting a new import of the same type shows a **Pick up where you left off**
  panel listing anything still open, with **Resume** and **Discard**.
- The wizard's address includes the job, so bookmarking or refreshing the page
  returns to the same import.

Unfinished jobs have written nothing to your event — **Discard** throws away the
file and the answers, and costs you nothing else.

## Supported sources

- **BikeReg** exports, with `First Name, Last Name, Email, Category, License, Team`.
- **RunSignup** exports, with similar columns plus `Bib`.
- **Generic CSVs** in any column layout, which you'll map yourself.
- **Results PDFs** — tables of `Place, Plate, Name, Team, Category, Time`. Time formats `H:MM:SS.ms`, `MM:SS.ms`, and `MM:SS` are all parsed.

## Import history

The Imports page lists every job with its status:

| Status | Meaning |
|---|---|
| **Uploaded** | File received, awaiting column mapping. Shows **Resume**. |
| **Mapped** | Mapping confirmed, waiting on preview/commit. Shows **Resume**. |
| **Committing** | Rows are being written now. |
| **Committed** | Done. Results column shows created/error counts. |
| **Cancelled** | You backed out before committing. |
| **Failed** | The job errored out — open it for the reason. |

Click **View** on a finished job to see row-level results, the licence check
for registrations imports, and re-download the error CSV. Unfinished jobs show **Resume** instead, which reopens the wizard
where you left it.

## Security notes

- Imports are admin-only. Every row is re-scoped server-side to your org and (for event imports) the event you're inside.
- Uploaded files are stored under a generated ID, so your filenames never hit disk.
- PDF parsing is sandboxed; embedded scripts can't run.
- License numbers and dates of birth are treated as personal data, and are never
  echoed back in error messages or logs.

## Tips

- **Always preview first.** A bad column mapping won't damage anything until you click Commit.
- **Email is the dedupe key for contacts.** Importing the same person twice updates them; it doesn't create duplicates.
- **Plates come over as strings**, preserving leading zeros (`007` stays `007`).
- **Emergency contacts need a name and a phone.** One without the other isn't
  stored — see [Emergency contacts](/organizers/events/imports#emergency-contacts).
- **Map the licence columns** on a registrations import. The export knows who's
  lapsed; see [Licence check](/organizers/events/imports#licence-check).
- For results PDFs, double-check the **time column** in the preview. Different
  platforms format times differently.
