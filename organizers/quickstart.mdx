This is the shortest complete path to taking entries for a race. Ten steps.
Each one links to the page with the full detail, so use this as the spine and
branch off when you need to.

<Note>
  Allow time to prepare your event documents, complete payment onboarding,
  and review the registration flow before announcing an opening date.
</Note>

## Before you start

Have these ready:

- A **logo** (square, under 5 MB).
- Your **waiver text**, or the PDF your insurer requires.
- Your **bank details and business info** for Stripe.
- The **race schedule**: categories, start times, and what you're charging.

## 1. Create your organization

[time2.bike/organizations/create](https://time2.bike/organizations/create).

Name, web address, contact details, brand color, logo. The web address is what
riders will see and what you'll print, so pick something you'll still want in
three years. It doesn't redirect if you change it later.

→ [Create an organization](/organizers/organization/create-organization)

## 2. Connect Stripe

**Settings → Billing**, then work through Stripe's onboarding.

<Warning>
  You cannot publish a paid event until Stripe is connected and onboarding is
  complete. Start early and follow any verification requests shown by Stripe;
  completion time varies.
</Warning>

→ [Billing & payouts](/organizers/organization/settings-billing) ·
[Stripe Connect](/platform/stripe-connect)

## 3. Upload a waiver

**Settings → Waivers**. You need at least one before anyone can register.

Waivers are org-level, then assigned to individual races, so write the general
one now and add discipline-specific ones later.

→ [Waivers](/organizers/organization/settings-waivers)

## 4. Invite your crew

**Settings → Team**. Registration desk, timing crew, whoever handles the money.

<Note>
  Review each person's permissions and event access before sending an invite.
  Roles preselect permissions, which you can adjust for the work they need to do.
</Note>

→ [Team & invites](/organizers/organization/settings-team)

## 5. Create the event

**Create event** from the dashboard. Enter basic info and location, then choose
**Create draft & add races**. Description, co-hosts, and sanctioning are optional
steps you can enable now or complete later.

Leave the status as **draft** while setting up. The draft preview is available
to authorized organization staff and Time2Bike staff.

→ [Create an event](/organizers/events/create-event)

## 6. Add your races

**Event → Races → New race**, once per race riders can enter.

For each race: name, format, capacity, gender restriction, and
whether it's a relay.

<Tip>
  Get the race *structure* right before you touch pricing. Pricing, waivers,
  and questions all attach to races, so splitting one race into two afterwards
  means redoing all three.
</Tip>

→ [Races list](/organizers/races/races-list)

## 7. Set pricing

Two levels:

- **Price schedules**, set on the organization: reusable early-bird, regular,
  and late tiers.
- **Race pricing** — apply a schedule to a race, or set a flat price.

Add discount codes now if you're running any.

→ [Price schedules](/organizers/pricing/price-schedules) ·
[Race pricing](/organizers/races/race-pricing) ·
[Discounts](/organizers/pricing/discounts)

## 8. Attach waivers and questions

- **Race → Waivers** — tick which waivers each race requires.
- **Event → Event setup → Questions** — anything you need to ask (t-shirt size, emergency
  contact, category self-select, club affiliation).

→ [Race waivers](/organizers/races/race-waivers) ·
[Custom questions](/organizers/events/questions)

## 9. Build the landing page

**Event → Public page → Event page** for the banner, description, schedule, FAQ, sponsors,
and photos. Leave the event in **draft** for now.

→ [Landing page builder](/organizers/events/landing-page-builder) ·
[Event sponsors](/organizers/events/event-sponsors)

## 10. Test the entry flow, then publish

Use the draft preview to place a **test entry** and review the waiver,
questions, displayed price, and confirmation email. Test entries skip payment,
so this does not test a live Stripe charge or payout.

Then, in order:

1. **Event → Registrations → Clear entries** to delete the test entries. Going
   live with them still in place puts fake riders on your public start list.
2. Open **Event setup → Settings** and submit the event for review. Request
   **published**, or **unlisted** for a link-only launch. Your event stays
   in draft preview while review is pending.

→ [Test entries](/organizers/events/test-entries) ·
[Event settings](/organizers/events/event-settings)

## Find your event tools

**Overview** shows required setup tasks before publication. Expand the
recommended improvements for optional items to review.
Use the main navigation for **Races**, **Participants**, **Check-in**,
**Live Timing**, and **Results**.

Expand **Event setup** for bibs and plates, questions, licenses, volunteers,
imports, and settings. **Public page** contains the event page editor, custom
pages, sponsors, and embeds. Open **Analytics** directly for event reports.

## Then, before race day

<Steps>
  <Step title="Assign bib numbers">
    **Event → Event setup → Bibs & plates**. Auto-assign a range or import a list.

    → [Bibs](/organizers/events/bibs)
  </Step>
  <Step title="Recruit volunteers">
    **Event → Event setup → Volunteers**, for opportunities, shifts, and race-day check-in.

    → [Volunteers](/organizers/events/volunteers)
  </Step>
  <Step title="Set up timing">
    There's nothing to create. Open the event's **Live Timing** tab and the
    timer is there, covering every race. Issue QR codes to your operators; they
    don't need accounts.

    → [Race-day runbook](/timing/race-day)
  </Step>
  <Step title="Print your start lists">
    **Event → Check-in → Print roster** — start lists, a call-up sheet, and a
    blank podium sheet for the awards tent.

    → [Check-in desk](/organizers/events/check-in)
  </Step>
  <Step title="Set up the check-in desk">
    **Event → Check-in** on a tablet is the desk itself: tick riders off, sort
    out unsigned waivers, missing licences and unpaid entries, and enter the
    people who turn up on the day. Load the roster while connected before
    using offline check-in, and verify that queued changes sync afterwards.

    → [Check-in desk](/organizers/events/check-in)
  </Step>
</Steps>

## Things people get wrong the first time

<AccordionGroup>
  <Accordion title="Leaving Stripe until the end" icon="triangle-exclamation">
    Verification isn't instant. Start it on day one, even if the event is
    months out.
  </Accordion>
  <Accordion title="Publishing before test-registering" icon="triangle-exclamation">
    Use [test entries](/organizers/events/test-entries) while the event is a
    draft. Check the public page after approval before sharing its link.
  </Accordion>
  <Accordion title="Pricing before the races are settled" icon="triangle-exclamation">
    Pricing, waivers, and questions all hang off races. Settle the race
    structure first.
  </Accordion>
  <Accordion title="Giving timing volunteers org accounts" icon="triangle-exclamation">
    Use timing links instead. They work on one event and nothing else.
    See [Volunteer links](/timing/crew/tokens-and-qr).
  </Accordion>
</AccordionGroup>
