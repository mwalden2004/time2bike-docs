Discount codes are managed at the **organization** level and can be scoped to series, events, races, or applied across the org. Manage them at **Pricing → Discounts**.

{/* IMAGE NEEDED: /organizations/[id]/pricing/discounts → discount code list with usage counts */}

## Create a code

1. Click **New code**.
2. Set:
   - **Code** — what riders type (case-insensitive).
   - **Kind**:
     - **Percent** off, stored as basis points (`1000` = 10%, `2500` = 25%).
     - **Amount** off, a flat dollar amount.
   - **Applies to**: anything you sell, or just one series, event, or race.
     Narrowing it reveals a picker for which one.
   - **Eligibility**, meaning **where the code can be redeemed**:
     - **Registration** (default), for race entry fees only.
     - **Merch**, for storefront merch and registration add-ons only.
     - **Both** — either / combined.
   - **Max uses** — total redemptions allowed across all riders. Blank = unlimited. See [Usage limits](#usage-limits).
   - **Per-user limit** — how many times a single rider can use it.
   - **Valid from / to** — optional date window.
3. **Save**.

Codes created before the eligibility flag existed default to **Registration** so old codes keep working.

## How it's applied

At checkout the rider enters the code on the **Review** step (or in the cart for merch). Time2Bike validates server-side: code exists, eligibility matches the cart type, scope matches the cart, within date window, max uses not exhausted, per-user limit not exhausted.

- **Percent codes** apply to the subtotal of eligible lines.
- **Amount codes** apply once, capped at the subtotal so they never go negative.

## Usage limits

**Max uses** and **Per-user limit** are enforced on race registration as well as
merch. A code with nothing left is refused outright.

### Carts bigger than the code

A rider entering themselves and a friend can have more eligible lines than the
code has uses left. Time2Bike discounts the first lines and charges the rest at
full price, rather than refusing the whole cart. The rider sees the discount on
their own entry before their friend's.

### Holds during checkout

A use is only *recorded* once money settles, which used to leave a window where
two people checking out at the same time could both spend the last use of a
single-use code. Registrations that are still pending now hold a use for up to
**60 minutes**, so the second checkout sees the code as exhausted.

An abandoned cart releases its hold when that hour is up, so a code is never
burned permanently by someone who walked away.

<Note>
  [Test entries](/organizers/events/test-entries) on a draft event never record
  a redemption, so they never hold one either. An organizer testing their own
  checkout can't burn a volunteer's free-entry credit.
</Note>

Per-user limits only apply when Time2Bike knows who's buying. An anonymous
checkout has no account to count against, so **Max uses** carries the limit
there.

Clearing an event's registrations recounts every affected code from the
redemptions that survive, so a code gets its uses back rather than drifting.

The **service fee is computed on the net subtotal after the discount**, so reducing the subtotal also reduces the fee.

## Merch storefront vs registration add-ons

- A code set to **Merch** or **Both** works in your public store only if
  **Applies to** is set to **any**. A code tied to a specific series, event, or
  race can't apply to a plain store order, because there's no race to match it
  against.
- When merch is purchased as an **add-on inside a registration**, event-scoped codes can apply as long as the registration is for that event.
- The cart checks a code as the rider types it, so they see "applied" or
  "invalid" straight away. It re-checks whenever the cart changes, so an
  amount-off code can't end up worth more than the order.
- A code that brings the total to exactly **$0.00** sends the order straight through without Stripe, but still records a redemption row.

## Redemptions

Every successful application writes a **redemption** row tied to the registration or merch order, so you can audit who used what and when. See [Redemptions](/organizers/pricing/redemptions).

## Volunteer reward codes

Codes issued for a completed volunteer shift show up in this list like any
other. They're single-use and prefixed `VOLFREE-` (a free entry) or `VOL-` (a
percent or amount reward). See [Volunteers](/organizers/events/volunteers#rewards).

## Lifecycle

- **Edit** — change kind/amount/scope/eligibility/limits.
- **Copy code** — copies to clipboard for sharing.
- **Delete** — disables the code for future use. Past redemptions stay on the registrations and orders they applied to.

See [Coupons & pricing](/riders/registering/coupons-and-pricing) for the rider's view.
