**Event → Volunteers** is a complete volunteer system: create opportunities, define roles and shifts, take public signups, and check people in on race day. Completed shifts can automatically issue a **discount code** for a future registration.

{/* IMAGE NEEDED: Event → **Volunteers** showing an effort with its roles and shift capacities */}

## Concepts

| Term | What it is |
|---|---|
| **Effort** | A top-level opportunity for an event (e.g. "Race-day course marshals"). |
| **Role** | A type of help within an effort (e.g. "Aid station lead"). |
| **Shift** | A time slot for a role with a **capacity**. |
| **Signup** | A volunteer claim on a shift. |
| **Reward** | What a completed shift earns — a free entry, or a percent or dollar discount. Issued when the shift is marked complete. |

## Create an effort

From the Volunteers tab click **New volunteer effort**. You'll set:

- **Name** and **description**.
- **Reward** — see [Rewards](#rewards) below. Issued automatically when a shift is marked complete.

Open the new effort to add **roles** and **shifts**. Each shift takes a role, a time window, and a capacity. Default shift = the whole event window with capacity 1.

### Shift instructions

Each shift has an **Instructions** field for what to bring, where to check in,
and who to find. It's shown on the public signup page and repeated in the confirmation
email, so a volunteer arriving on race morning has it without digging up the
page again.

<Warning>
  Volunteers read these instructions. Anything you don't want them to see goes
  in the shift's **admin note** instead. That one never leaves your
  organization.
</Warning>

## Rewards

Pick what a completed shift earns:

| Reward | What the volunteer gets |
|---|---|
| **No reward** | Nothing. No code is issued. |
| **Free entry** | A 100%-off entry credit. |
| **% off** | A percentage off one registration. |
| **$ off** | A flat amount off one registration. |

### Where it can be spent

Each reward has a **redeemable at** setting:

- **This event** — the code only works on this event, which in practice makes
  it a next-edition code.
- **Any of our races** — the code works on any race your organization runs.

**Free entry** defaults to *any of our races*. A volunteer has already worked
the event they signed up for, so a credit locked to that event would be
unspendable. Percent and amount rewards default to *this event*.

### What the credit covers

By default a reward covers the **entry fee only**. Two fees pass through unless
you opt in:

- **Permitting / one-day license fee** — that money is owed to a sanctioning
  body, not to you.
- **Series replacement-plate fee** — that covers a physical plate.

Tick **also covers license fee** or **also covers plate fee** on the effort if
you want your reward to absorb them.

### How the code is issued

When you mark a shift complete, Time2Bike generates a single-use discount code
and emails it to the volunteer. Free entries get a `VOLFREE-` prefix and
everything else gets `VOL-`, so a 100%-off code is obvious at a glance in your
[discount code list](/organizers/pricing/discounts).

Because these codes are single-use, Time2Bike now holds a use while a rider is
mid-checkout, so two people can't both spend the last one. See
[Discount codes](/organizers/pricing/discounts#usage-limits).

A **no-show** or a cancelled signup never gets a code.

## Take public signups

Once the effort is **open**, it's visible at:

- The event page's **Volunteer** action.
- The **Want to volunteer?** card on your event page, while shifts are open.

Public users see open shifts and the reward, if there is one. They can't see who
else has signed up, only the **spots remaining** count.

The event page also previews your opening: while an effort has an open shift,
riders see a **Want to volunteer?** card with the total spots and shifts open,
the reward on offer, and the next few shifts by role, time, and location. It
disappears on its own once everything is filled.

Close an effort to stop signups without deleting it.

## Add a volunteer manually

From the effort's **Signups** table click **Add volunteer**. Useful for in-person additions and people without email accounts.

## Race-day check-in

The **Signups** table supports:

- **Move shift** — drag someone from a full slot to one that still needs help.
- **Check in / Check out** — sets the volunteer's status to `checkedIn` (and records the timestamp).
- **No-show** — used after the fact to flag people who didn't appear. Their reward isn't issued.
- **Cancel** — releases their spot back to the pool.

Each signup also gets a **QR token** in their confirmation email. If you're scanning at the volunteer tent, the scanner page on the same effort handles check-in.

## Print a check-in sheet

Click **Print sheet** on a shift for a paper roster with name, phone, role, and check-boxes. Useful when network is spotty at the start/finish.

## Communicate

- **Bulk email** — select rows, click **Email**. Sending the same announcement twice won't double up in anyone's inbox.
- **Optional SMS reminders** — sent the day before via the platform's SMS service. Volunteers opt in at signup; STOP replies are respected.

## Rewards

When you mark a shift **completed** for a signup, the configured reward is issued:

- A unique single-use discount code is generated.
- The code lands in the volunteer's email.
- The code is valid on any future registration with your organization.

Marking the same shift complete twice won't issue a second code.

## Export

**Export CSV** dumps the current signups table including status and hours. Background-check notes (if used) are excluded from the default export.

## Dashboard metrics

The effort detail page shows:

- Total signups and capacity fill.
- Shifts fully staffed vs. understaffed.
- Checked-in count and no-shows.
- A **gaps** panel listing shifts that still need help, so you know where to recruit.
